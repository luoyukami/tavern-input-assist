# 酒馆输入助手（tavern-input-assist）

SillyTavern 前端扩展：在输入框最左侧放一个图标按钮，点开一个向上弹出的面板，用它生成回复选项或把一句简短想法扩写成完整消息，一键送进输入框。

## 功能

- **选项**：固定 6 条，每条位置有固定角色，点一条就写进输入框。每条有自己的不透明底色、左侧色条和序号色：

  | # | 角色 | 序号色 | 底色 |
  | --- | --- | --- | --- |
  | 1–3 | 正常分支（三条走向要不同） | 雾蓝 / 灰绿 / 米棕 | `#262b33` `#242e2b` `#302c25` |
  | 4 | 新奇：脑洞、跳出常规 | 淡紫 | `#2c2735` |
  | 5 | 邪恶：阴暗、放肆、更具侵略性 | 暗红 | `#332628` |
  | 6 | 跳跃：大幅推进时间线 | 金棕 | `#332d21` |

- **扩写**：在面板里写一句想法（例如「我犹豫了一下，还是问了她的名字」），由模型补成一条完整消息，直接注入输入框，末尾留一份便于再取。
- **世界书**：选项生成和扩写都会带上酒馆当前激活的世界书条目（连 `@Depth` 位置的也一起），背景信息够了，选项才贴设定。可以在设置里关掉，或限制字数上限。
- **润色**：把某一层角色回复的正文重新润色一遍，直接替换酒馆里的这条消息。润色过的消息，按钮行里会多一个笔形图标：还没有记录时点它是「润色这一层」，有记录时点它在**原版 / 润色版**之间切。两份文本都留着，切换是逐字无损的。见下文「正文润色是怎么工作的」。
- **自动**：开启后，每次模型回复结束就自动生成一轮选项，按钮上亮一个小圆点提醒。生成被手动停止、最新楼层是用户自己的消息、或这一层已经生成过时自动跳过，不浪费请求。自动润色开着时先润色再生成选项，让选项基于润色后的正文。

按钮注入在 `#nonQRFormItems` 的第一个位置（`order: -1`），排在酒馆原有菜单栏（`#leftSendForm`，`order: 1`）的左边，也就是整个输入框的最左端。尺寸比原有图标按钮大一号。

## 安装

把整个目录放进酒馆的扩展目录即可，不需要重启酒馆：

```
<SillyTavern>/public/scripts/extensions/third-party/tavern-input-assist/
```

刷新浏览器页面，酒馆的扩展加载器会自己发现它。

## 设置

面板的「设置」页分三块：

### 连接

| 项 | 说明 |
| --- | --- |
| 连接方式 | **酒馆后台转发**（默认，推荐）：由酒馆服务器发请求，需要酒馆 `config.yaml` 里 `enableCorsProxy: true`。**浏览器直连**：由当前设备发请求，要求渠道允许跨域。 |
| API 地址 | 填基础地址，例如 `http://127.0.0.1:8317/v1`。粘贴完整的 `/v1/chat/completions` 也会被自动裁回基础地址。 |
| API Key | 渠道的客户端密钥，可留空。「记住密钥」勾上才会写进酒馆设置。 |
| 文字模型 | 选项生成和扩写共用。可手输，也可点「读取模型」拉列表后点选。 |

### 润色（面板的「润色」页）

| 项 | 说明 |
| --- | --- |
| 润色哪一层 | 列最近 20 层角色回复，默认最新一层。点消息按钮行里的笔也会把目标切到那一层。 |
| 角色回复结束后自动润色 | 默认关。只跑最新一层，守卫与自动选项同一套。 |
| 润色模型 | 留空＝跟主模型一样。润色与主流程共用连接方式、地址与密钥，只是模型名可以单独指定（例如专门用不审查的那个）。 |
| 润色时附带的上下文层数 | 默认 2，0–20。只用来让模型知道人称、语气与处境，这些楼层不会被润色。 |
| 启用内置剔除名单 | 默认开。关掉后只按酒馆的正则脚本 + 下面补的块名取正文。 |
| 额外剔除的块名 | 见下文「正文段切分」。预设里有内置名单没覆盖到的块名就补在这里，逗号或空格分隔，支持 `*` 通配。 |
| 润色的预设 | 职能范围写在这里：清掉八股与 AI 味、重新设计动作和台词让角色像活人，**只保大意**（情节走向、人物关系、事实性细节不动），句子结构和措辞可以大改。可用 `{{text}}`（要改写的正文）、`{{chat}}`、`{{char}}`、`{{user}}`、`{{worldinfo}}`。不写 `{{text}}` 时正文会自动补在末尾。 |

后台转发模式下密钥走 **`x-api-key`** 而不是 `Authorization`：`/proxy/` 路由挂在酒馆自己的 HTTP Basic 认证后面，浏览器会把酒馆登录塞进同一个 `Authorization` 头，两者只能二选一。CLIProxyAPI 两种头都接受，所以把它放进 `x-api-key` 就能同时满足酒馆登录和上游鉴权。

### 行为

| 项 | 说明 |
| --- | --- |
| 上下文层数 | 1–100，默认 8。取最近这么多层有效聊天（跳过系统楼层）。 |
| 把世界书一起发过去 | 默认开。用酒馆自己的激活逻辑取当前条目。 |
| 世界书字数上限 | 默认 4000，超过就截断并注明。 |
| 最长等待 | 10–600 秒，默认 120。 |
| 点选项时怎么写入输入框 | **追加**（默认）会保留你已经打好的内容并换行接上；**替换**直接覆盖。输入框为空时两者一样。 |
| 模型回复结束后自动生成选项 | 见上文「自动」。 |

### 提示词

两个预设都可以改，支持占位符：

- 生成选项：`{{chat}}`、`{{char}}`、`{{user}}`、`{{count}}`、`{{worldinfo}}`
- 扩写：`{{input}}`、`{{chat}}`、`{{char}}`、`{{user}}`、`{{worldinfo}}`

`{{worldinfo}}` 展开成「【世界设定】+ 内容 + 空行」，没有世界书时就是一个空串（不会留下空标题）。默认预设把它放在聊天记录前面；预设里不写它时，世界设定也会自动贴在聊天记录之前。

`{{char}}` 取的是 `name2` / 角色卡上的名字，未必等于剧情里的称呼（可能只是卡名或文件名），所以默认预设刻意不引用它 —— 聊天记录里每句话都自带真实称呼，模型看得出来。`{{user}}` 同理，优先用消息里的名字。

六个位置的角色分工写在生成选项的预设里（第 1–3 条 · 正常分支、第 4 条 · 新奇、第 5 条 · 邪恶、第 6 条 · 跳跃），想改角色就改那几行 —— UI 的颜色和标签是按**位置**贴的，不依赖预设文字。

预设里不写 `{{chat}}` 时，聊天记录会自动补在末尾（免得误删占位符后模型完全看不到上下文）。「恢复默认预设」可以一键还原。

面板里两个功能各自有一份「预览会发送的内容」，改完预设可以直接看最终提示词。

## 正文润色是怎么工作的

- **正文以「真正发给模型的那份」为准**：先过酒馆自己的正则管线（`regex/engine.js` 的 `getRegexedString(mes, AI_OUTPUT, { isPrompt: true, depth })`，和酒馆拼提示词时同一个调法），预设里「只改发送」的规则删掉了什么，正文里就没有什么；那些被删掉的区间在替换时原位保留（`<UpdateVariable>` 这类要交给别的扩展解析的块不能丢）。拿不到这个模块就退回内置名单；面板上可以关掉内置名单，只留正则脚本。
- **正文段切分（思维链与面板不算正文）**：有些预设会把思维链、变量更新、状态面板、选项列表、图片块写进 `mes`。这些东西既不送去改写、也不进对照，替换时原位逐字保留。判断分两层：① 按块名（内置认 think/reasoning/analysis/scratchpad、update*/json_patch、*status*/*state*/*panel*、*option*/*choice*、image*/pic/img，中文标签名也认）；② 按内容长相（纯文件名、JSON、`[键|值]` 数据行）。名字不在名单里、内容又是正常文字的块按正文处理 —— 宁可多留，不能把正文丢掉。正文容器的标签（`<content>`、`<Interleaving>`、`<lily_story>` 这类）保留，只换里面的文字，所以预设的排版与正则不受影响。只剩思维链/面板的楼层会直接说明原因，不发请求。
- **出厂预设的定位是改稿，不是同义替换**：清掉八股与 AI 味（套话模板、副词堆砌、翻译腔、解释情绪、升华式结尾、助手式台词），重新设计角色的动作与台词，让角色像活人开口。只保大意 —— 信息量、情节走向、人物关系、事实性细节（人名、地名、物件、数字、伤口、身体状态）不动，句子结构、措辞、动作与台词可以大尺度重写。长度区间 60%–150%。
- **出厂预设升级**：改动出厂预设时会把上一版收进历史清单，只升级那些逐字还是旧版的安装，用户自己改过的一个字都不动。
- **切换是真改正文**：把 `mes` 换成选中的那一版，`updateMessageBlock()` 重渲染、`saveChat()` 落盘，再补发 `MESSAGE_UPDATED` 让其他扩展（例如生图插件）知道这一层内容变了。显示的和发给模型的始终是同一份，不会出现「看着原版、实际发的是润色版」。
- **记录的键是正文的哈希**，不是楼层号：楼层会被删、被插入、被 swipe 换掉，文本哈希不会。记录存在聊天自己的 `chat_metadata` 里（跟着聊天文件走），另在扩展设置里按聊天 ID 留一份镜像，给分支聊天用「从主聊天继承」补回来 —— 酒馆的 `createBranch` 只带得走 `main_chat`，父聊天的 metadata 不会跟过来。
- **当前显示的是哪一版靠正文本身推导**，不存单独的开关字段，所以不会有状态对不上的时候；刷新页面、切 swipe 之后都能重新认出来。
- **手改楼层**：改的时候显示的是哪一版，改动就接进哪一版（原版与润色版两个方向都不丢）。判断不出改的是哪一版时记录保持不动，按钮会显示成「手改过」。
- **应用前有四道闸**，任一命中都不自动替换，改成在面板里给原版／润色版对照，人工点「仍然应用这份结果」才写回：空输出或只剩空白 · 和原文一模一样 · 缩短到原文 50% 以下（像是被截断或被审核掉） · 涨到 2 倍以上（可能加了原文没有的内容） · 原文里的 `{{宏}}` 或 HTML 标签在结果里丢了。
- **请求期间那一层被改过**（swipe、重新生成、手改，正文哈希对不上）就丢弃这次结果，绝不覆盖新内容。
- 正文换了会顺手作废该层的 token 计数缓存，让酒馆自己重算。

## 世界书是怎么取的

调用酒馆自己的 `context.getWorldInfoPrompt(chatStrings, 8192, true, scanData)` —— 也就是酒馆真正发消息时用的那套激活逻辑，关键词匹配、递归扫描、角色过滤、位置预算全照它的规则算，所以这里拿到的和实际发给模型的那份一致。**不自己解析世界书做关键词匹配**，那样永远和酒馆对不上。

- **第一个参数必须是字符串数组，且深度 0 是最新一条**，照抄酒馆自己的 `coreChat.map(x => `${x.name}: ${x.mes}`).reverse()`。传消息对象进去会死在 `WorldInfoBuffer` 的 `messages[depth].trim()` 上（对象没有 `trim`），异常被静默吞掉 —— 症状是「世界书没加载」，而且日志里一句报错都没有。
- `isDryRun = true`：只算内容，不触发 `WORLD_INFO_ACTIVATED` 事件，不干扰酒馆自己的状态。
- `scanData` 带上当前角色卡的 description / personality / scenario / creatorNotes，让「限定角色」的条目也能命中。
- 返回值里的 `worldInfoString` **只有 before/after 位置的条目**；`@Depth` 位置的在 `worldInfoDepth[].entries` 里，要单独补上，否则会丢。
- `scanData.trigger` 要填 `'normal'`（普通生成）；不填就是 `undefined`，带触发条件的条目会静默不激活。
- 拿不到（旧版本没这个接口、没有世界书、抛错）就静默返回空串，选项生成照常跑。

## 模型输出怎么解析

模型输出一律当不可信文本处理：

- 先剥思维块（`<think>`/`<thinking>`/`<reasoning>`，包括未闭合的）和代码围栏。
- 取第一个**括号配平**的 JSON 数组（跳过字符串内部与转义引号），也接受 `{"options": [...]}` 这种包了一层的形态。
- 模型没照格式走时按行兜底拆分，去掉 `1.` / `-` 之类的项目符号。
- 逐条校验：必须是非空字符串、去重、单条不超过 400 字、不超过设定的条数。
- 扩展只输出干净的文本，不解释、不补全。

扩写结果超过 2000 字会被整条丢弃并提示重试，而不是截断成半句话。

## 开发

```bash
node --test tests/*.test.js     # 纯逻辑单测（连接、校验、注入合并、自动守卫、输出解析、润色记录与判定）
node dev/server.mjs             # 本地沙盒 http://127.0.0.1:8766
```

沙盒复刻了酒馆的输入区结构（`#nonQRFormItems` > `#leftSendForm` + `#send_textarea` + `#rightSendForm`）与主题变量，并带一个模拟渠道（`/v1/models`、`/v1/chat/completions`）和 `/proxy/` 转发，不需要真实密钥、不联网。

- `?fresh=1` 打开是**全新安装**状态（没有已存设置、模型名留空），用来测第一次配置的路径
- `/mock/state` 看请求数、转发头记录
- `/mock/control` 改 `proxyEnabled` / `failChat` / `chatDelay` 等，用来验错误提示

按住 `order` 这件事值得记一笔：`#send_textarea` 是 `order: 3`、`#leftSendForm` 是 `order: 1`，所以按钮用 `order: -1` 才稳。

# 酒馆输入助手（tavern-input-assist）

SillyTavern 前端扩展：在输入框最左侧放一个图标按钮，点开一个向上弹出的面板，用它生成回复选项或把一句简短想法扩写成完整消息，一键送进输入框。

## 功能

- **选项**：固定 6 条，每条位置有固定角色，点一条就写进输入框。每条有自己的不透明底色、左侧色条和序号色：

  | # | 角色 | 序号色 | 底色 |
  | --- | --- | --- | --- |
  | 1–3 | 正常分支（三条走向要不同） | 雾蓝 / 灰绿 / 米棕 | `#262b33` `#242e2b` `#302c25` |
  | 4 | 新奇：脑洞、跳出常规 | 淡紫 | `#2c2735` |
  | 5 | 邪恶：阴暗、放肆、更具侵略性 | 暗红 | `#332628` |
  | 6 | 跳跃：大幅推进时间线 | 金棕 | `#332d21` |

- **扩写**：在面板里写一句想法（例如「我犹豫了一下，还是问了她的名字」），由模型补成一条完整消息，直接注入输入框，末尾留一份便于再取。
- **世界书**：选项生成和扩写都会带上酒馆当前激活的世界书条目（连 `@Depth` 位置的也一起），背景信息够了，选项才贴设定。可以在设置里关掉，或限制字数上限。
- **自动**：开启后，每次模型回复结束就自动生成一轮选项，按钮上亮一个小圆点提醒。生成被手动停止、最新楼层是用户自己的消息、或这一层已经生成过时自动跳过，不浪费请求。

按钮注入在 `#nonQRFormItems` 的第一个位置（`order: -1`），排在酒馆原有菜单栏（`#leftSendForm`，`order: 1`）的左边，也就是整个输入框的最左端。尺寸比原有图标按钮大一号。

## 安装

把整个目录放进酒馆的扩展目录即可，不需要重启酒馆：

```
<SillyTavern>/public/scripts/extensions/third-party/tavern-input-assist/
```

刷新浏览器页面，酒馆的扩展加载器会自己发现它。

## 设置

面板的「设置」页分三块：

### 连接

| 项 | 说明 |
| --- | --- |
| 连接方式 | **酒馆后台转发**（默认，推荐）：由酒馆服务器发请求，需要酒馆 `config.yaml` 里 `enableCorsProxy: true`。**浏览器直连**：由当前设备发请求，要求渠道允许跨域。 |
| API 地址 | 填基础地址，例如 `http://127.0.0.1:8317/v1`。粘贴完整的 `/v1/chat/completions` 也会被自动裁回基础地址。 |
| API Key | 渠道的客户端密钥，可留空。「记住密钥」勾上才会写进酒馆设置。 |
| 文字模型 | 选项生成和扩写共用。可手输，也可点「读取模型」拉列表后点选。 |

后台转发模式下密钥走 **`x-api-key`** 而不是 `Authorization`：`/proxy/` 路由挂在酒馆自己的 HTTP Basic 认证后面，浏览器会把酒馆登录塞进同一个 `Authorization` 头，两者只能二选一。CLIProxyAPI 两种头都接受，所以把它放进 `x-api-key` 就能同时满足酒馆登录和上游鉴权。

### 行为

| 项 | 说明 |
| --- | --- |
| 上下文层数 | 1–100，默认 8。取最近这么多层有效聊天（跳过系统楼层）。 |
| 把世界书一起发过去 | 默认开。用酒馆自己的激活逻辑取当前条目。 |
| 世界书字数上限 | 默认 4000，超过就截断并注明。 |
| 最长等待 | 10–600 秒，默认 120。 |
| 点选项时怎么写入输入框 | **追加**（默认）会保留你已经打好的内容并换行接上；**替换**直接覆盖。输入框为空时两者一样。 |
| 模型回复结束后自动生成选项 | 见上文「自动」。 |

### 提示词

两个预设都可以改，支持占位符：

- 生成选项：`{{chat}}`、`{{char}}`、`{{user}}`、`{{count}}`、`{{worldinfo}}`
- 扩写：`{{input}}`、`{{chat}}`、`{{char}}`、`{{user}}`、`{{worldinfo}}`

`{{worldinfo}}` 展开成「【世界设定】+ 内容 + 空行」，没有世界书时就是一个空串（不会留下空标题）。默认预设把它放在聊天记录前面；预设里不写它时，世界设定也会自动贴在聊天记录之前。

`{{char}}` 取的是 `name2` / 角色卡上的名字，未必等于剧情里的称呼（可能只是卡名或文件名），所以默认预设刻意不引用它 —— 聊天记录里每句话都自带真实称呼，模型看得出来。`{{user}}` 同理，优先用消息里的名字。

六个位置的角色分工写在生成选项的预设里（第 1–3 条 · 正常分支、第 4 条 · 新奇、第 5 条 · 邪恶、第 6 条 · 跳跃），想改角色就改那几行 —— UI 的颜色和标签是按**位置**贴的，不依赖预设文字。

预设里不写 `{{chat}}` 时，聊天记录会自动补在末尾（免得误删占位符后模型完全看不到上下文）。「恢复默认预设」可以一键还原。

面板里两个功能各自有一份「预览会发送的内容」，改完预设可以直接看最终提示词。

## 世界书是怎么取的

调用酒馆自己的 `context.getWorldInfoPrompt(chat, 8192, true, scanData)` —— 也就是酒馆真正发消息时用的那套激活逻辑，关键词匹配、递归扫描、角色过滤、位置预算全照它的规则算，所以这里拿到的和实际发给模型的那份一致。**不自己解析世界书做关键词匹配**，那样永远和酒馆对不上。

- `isDryRun = true`：只算内容，不触发 `WORLD_INFO_ACTIVATED` 事件，不干扰酒馆自己的状态。
- `scanData` 带上当前角色卡的 description / personality / scenario / creatorNotes，让「限定角色」的条目也能命中。
- 返回值里的 `worldInfoString` **只有 before/after 位置的条目**；`@Depth` 位置的在 `worldInfoDepth[].entries` 里，要单独补上，否则会丢。
- 拿不到（旧版本没这个接口、没有世界书、抛错）就静默返回空串，选项生成照常跑。

## 模型输出怎么解析

模型输出一律当不可信文本处理：

- 先剥思维块（`<think>`/`<thinking>`/`<reasoning>`，包括未闭合的）和代码围栏。
- 取第一个**括号配平**的 JSON 数组（跳过字符串内部与转义引号），也接受 `{"options": [...]}` 这种包了一层的形态。
- 模型没照格式走时按行兜底拆分，去掉 `1.` / `-` 之类的项目符号。
- 逐条校验：必须是非空字符串、去重、单条不超过 400 字、不超过设定的条数。
- 扩展只输出干净的文本，不解释、不补全。

扩写结果超过 2000 字会被整条丢弃并提示重试，而不是截断成半句话。

## 开发

```bash
node --test tests/*.test.js     # 纯逻辑单测（连接、校验、注入合并、自动守卫、输出解析）
node dev/server.mjs             # 本地沙盒 http://127.0.0.1:8766
```

沙盒复刻了酒馆的输入区结构（`#nonQRFormItems` > `#leftSendForm` + `#send_textarea` + `#rightSendForm`）与主题变量，并带一个模拟渠道（`/v1/models`、`/v1/chat/completions`）和 `/proxy/` 转发，不需要真实密钥、不联网。

- `?fresh=1` 打开是**全新安装**状态（没有已存设置、模型名留空），用来测第一次配置的路径
- `/mock/state` 看请求数、转发头记录
- `/mock/control` 改 `proxyEnabled` / `failChat` / `chatDelay` 等，用来验错误提示

按住 `order` 这件事值得记一笔：`#send_textarea` 是 `order: 3`、`#leftSendForm` 是 `order: 1`，所以按钮用 `order: -1` 才稳。
